연결 이론

저장 버튼은 저장소에 요청을 보냅니다.

API(에이피아이)는 프로그램끼리 정해진 방식으로 요청하고 응답하는 통로입니다.

  1. 웹페이지: “10월 영업B 실적 720만 원을 저장해 주세요.”
  2. 저장소: “이 사용자에게 허용된 입력인가요?”를 확인합니다.
  3. 저장소: 성공 또는 실패 결과를 돌려줍니다.
  4. 웹페이지: 실제 결과를 확인한 뒤 “저장됨” 또는 오류를 보여줍니다.
오늘은 API 코드를 직접 작성하지 않습니다. Codex에 연결을 요청하고, 실제로 저장되는지 확인합니다.

원본은 보존하고 실습용 결과를 따로 만듭니다.

현재 프로젝트의 index.html 하나로 작동하는 KPI 화면에서 다음 실습 파일을 만들어줘.
먼저 세션 작업공간의 절대 경로와 index.html의 실제 위치를 확인해줘.
작업공간 밖으로 탐색하지 말고 기존 코드는 보존해줘.
원본을 유지하고 프로젝트 안 실습앱/에 결과를 만들어줘.
현재 폴더가 이미 실습앱이면 경로를 중복해서 붙이지 마.

1. 기존 HTML의 스타일은 style.css, 화면 동작은 app.js로 분리해줘.
2. 계산·값 검사·샘플 데이터는 core.js로 분리해줘.
3. 실습앱/index.html은 상대 경로로 이 파일들을 읽게 하고 같은 화면·필터·계산을 유지해줘.
4. 기존 가상 데이터를 data/kpi.json과 UTF-8 data/kpi.csv에도 만들어줘.
   파일을 직접 여는 실습에서는 fetch 실패가 없게 core.js의 샘플을 사용해줘.
   JSON·CSV는 가져오기와 원본 비교용 사본이라고 설명해줘.

화면에서 확인한 것과 추가 설계를 구분해줘. 외부 배포·커밋·실제 DB 변경은 하지 마.

실습 2 · DB

앱 사용자와 공개 설정을 준비합니다.

Supabase 계정을 만들었다고 앱 로그인이 자동으로 생기는 것은 아닙니다.

  1. Authentication → Users에서 교육용 앱 사용자를 준비합니다. 이메일·비밀번호 로그인에 사용할 확인 완료 사용자를 준비하거나 이메일 확인 절차를 마칩니다.
  2. 프로젝트의 Connect 또는 API 설정에서 Project URL과 publishable key를 확인합니다.
  3. 프로젝트의 config.js에 공개 설정을 넣습니다. 아래 값은 자리표시자이므로 실제 값으로 바꿉니다.
window.KPI_CONFIG = {
  supabaseUrl: "YOUR_PROJECT_URL",
  supabasePublishableKey: "YOUR_PUBLISHABLE_KEY"
};
앱 비밀번호·DB 비밀번호·비밀키는 config.js에 넣지 않습니다. config.js는 앱 코드보다 먼저 읽혀야 합니다.

강사와 함께 확인

내 자료만 보이는지는 강사와 함께 확인합니다.

수강생은 계정별 화면을 확인하고, 직접 요청을 보내는 기술 검사는 강사가 담당합니다.

  1. 사용자 A로 로그인해 저장한 숫자를 확인합니다.
  2. 로그아웃하면 A의 DB 자료가 화면에서 사라지는지 봅니다.
  3. 시험 사용자 B로 로그인해 A의 자료가 보이지 않는지 봅니다.
강사 확인: 화면에서 숨겨진 것뿐 아니라 DB에서도 타인 자료 조회·수정·삭제가 막혀 있어야 합니다. 직접 API 검사는 강사가 시험 계정으로 진행합니다.

선택 확장 · 파일 가져오기

외부 파일을 읽는 것과 DB에 저장하는 것은 다릅니다.

CSV는 구분자로 나눈 텍스트, XLSX는 여러 시트가 들어갈 수 있는 엑셀 파일입니다.

순서화면과 처리
1. 선택·읽기CSV 인코딩과 헤더 확인 / XLSX 시트 선택
2. 열 연결기준월 → month, 부서명 → team, 목표액 → target, 실적액 → actual
3. 미리보기·검사행 번호·변환값·오류·중복을 표시
4. 사용자 확인추가할 행과 제외할 행의 수를 확인
5. 저장·재조회확인한 유효 행만 본인 소유로 저장, DB 결과 표시
권장 기본값: 기존 사용자·월·부서와 겹치는 행은 건너뛰고 이유를 보여줍니다. 기존 값 덮어쓰기는 별도의 선택과 확인이 필요합니다.

업로드 전에 다섯 가지를 결정합니다.

아래 제한은 수업용 제안이며 구현할 때 적용 여부를 확인합니다.

설계 질문수업용 권장안 · 제안
어떤 파일인가?UTF-8 CSV·XLSX, 최대 5MB·데이터 1,000행. XLS·XLSM 제외
어떤 시트·열인가?XLSX 시트 선택, 필수 열 연결. 다중 시트 자동 합치기 금지

선택 확장 · 업로드 프롬프트

파일 업로드는 “미리보기 → 확인 → 저장”으로 요청합니다.

확인 전에는 실제 DB에 저장하지 않도록 명시합니다.

기존 KPI 앱에 CSV·XLSX 가져오기를 추가해줘. 기존 구조·DB 규칙을 먼저 확인해줘.
원본 파일은 서버에 보관하지 않고 브라우저에서 읽은 KPI 행만 DB에 저장해줘.
수업용 제한은 5MB·데이터 1,000행으로 적용하고 XLS·XLSM은 거절해줘.
CSV는 UTF-8 BOM·따옴표·셀 안 쉼표·줄바꿈을 처리하는 파서를 써줘.
XLSX는 시트 선택을 제공하고 수식 셀은 오류 처리하며 외부 링크를 실행하지 마.
월·부서·목표·실적 열을 사용자가 연결하고 변환 결과를 미리 보게 해줘.
필수값·월 형식·부서 공백·0 이상 안전한 정수 금액을 검사해줘.
행 번호별 오류, 파일 내부 중복, 본인 DB의 월·부서 중복을 표시해줘.
중복은 건너뛰고 기존 값을 덮어쓰지 마. 유효 행 수를 확인한 뒤에만 저장해줘.
파일의 id·user_id·역할 값은 저장값으로 사용하지 말고 로그인 사용자 소유로 저장해줘.
RLS·DB 제약도 유지하고 동시 업로드의 중복 오류를 처리해줘.
저장 중 중복 클릭을 막고 계정 전환 때 미리보기·진행 상태를 초기화해줘.
묶음 저장 일부 실패는 전체 성공으로 표시하지 말고 성공·실패·건너뜀을 구분해줘.
실패 행만 재시도하게 하고 재조회 후 표·차트·합계를 갱신해줘.
정상·빈 파일·잘못된 값·중복·수식·한도 초과·계정 전환을 검증해줘.
추가 라이브러리는 출처·버전을 확인하고 선택 이유를 설명해줘.
실제 업무 파일·DB 변경·외부 배포·커밋 없이 구현하고 미확인 항목을 알려줘.
